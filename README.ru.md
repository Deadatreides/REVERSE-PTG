# Обратный PTG (rptg kit)

[English version](README.md)

**ТЗ превращается в граф карточек с типами. Листья пишут дешевые модели. Работу принимают готовые инструменты, а не
модели.**

Плагин Claude Code для разработки программы на Python по ТЗ:
1. **Главный чат (Opus) — архитектор.** Пишет `spec.md`, корень, общие типы и детей корня.
2. **Корень утверждаете вы.**
3. **Составные узлы раскладывают проектировщики** — субагенты Sonnet.
4. **Тела листьев пишут исполнители** — субагенты Haiku, строго по карточке.

Карточка — обычный модуль Python:
* подписи с типами;
* условия deal;
* число решений `D` и примеры doctest;
* тело `raise NotImplementedError`.

Сдачу принимают mypy, tach, ruff, deal lint, doctest с Hypothesis, CrossHair и radon. Лестница кода — haiku → sonnet
→ opus. Что откуда взято, как устроено и что проверено — [docs/KIT.md](docs/KIT.md).

**Установка.**

```bash
git clone https://github.com/Deadatreides/REVERSE-PTG.git
cd REVERSE-PTG
python -m venv .venv-kit
.venv-kit/Scripts/python -m pip install -r requirements-kit.txt
```

Затем в Claude Code:

```
/plugin marketplace add Deadatreides/REVERSE-PTG
/plugin install rptg@rptg-local
```

Сервер плагина запускается через `rptg_kit/launch.py`. Python он выбирает так:
1. `RPTG_KIT_PYTHON`;
2. иначе `.venv-kit` рядом с плагином;
3. иначе тот, которым запущен.

Чтобы работать с рабочей копией kit, а не с кэшем Claude Code, впишите путь к ней в `~/.rptg-kit/home`.

**Работа.** Новый чат и фраза: «разработай ПО по ТЗ `<файл>` в папке `<папка>»`. После утверждения корня kit сам
запускает исполнителей волнами: `python -m rptg_kit.run <папка> --detach`.

**Что им собрано.** Весь полный движок [PTG-MEM](https://github.com/Deadatreides/PTG-MEM) 0.3:
* memcore — 17 билетов;
* memshell;
* ptgfull — 25 билетов, 2 381 строка;
* ptgcore — 43 билета, исполнители — $0,69.

**Цена.** Через kit вышло дороже, чем писать одним сильным чатом:
* memcore с memshell — $33,97 против $12,6–14,6;
* ptgfull — $16,8 против $8–12.

Исполнители дешевы. Дорог главный чат, если он разбирает уведомления субагентов. Теперь kit запускает исполнителей сам,
и уведомлений нет.

**Правила экономии токенов для Claude** — [CLAUDE.md](CLAUDE.md). Главное правило: вышестоящая модель получает
сигнал только в конце. Те же правила несут сервер, навык и роли.

## Первое ядро (27.09–08.10.2026)

Ниже — прежнее ядро `rptg/` и оболочка `rptg_host/`. Они лежат как были. Живого прогона на моделях у них не было, а
проверка рынком 08.10 показала, что их замысел уже закрыт: Kiro, Spec Kit, MetaGPT, Parsel. Поэтому с 10.10 работает
kit.

Программа, которая строит программы по графу:

* **архитектор** пишет центральный узел, его рёбра и общую карту сети;
* **конструкторы** раскладывают составные узлы на дочерние узлы и рёбра между ними — на любую
  глубину, но только там, где это необходимо;
* **исполнители** пишут код финальных узлов, рёбер не касаясь.

Весь соединительный код генерирует скрипт. Он же принимает каждый результат только
детерминированными проверками, у которых есть свои контрольные случаи.

Какая модель делает какой узел, решает маршрутизация. Порядок такой:

1. ручные назначения;
2. измеренная таблица компетенций — успех каждой модели по классам работы на одинаковых эталонных
   задачах;
3. пока таблицы нет — прикидка по карточке.

Модели — любых поставщиков вперемешку: Claude, GPT, Gemini, Grok, всё, что есть в OpenRouter,
локальные через llama.cpp или OpenAI-совместимый сервер.

Статус (04.10.2026): ядро построено его же методом — семь подсистем по карточкам, соединительный код
пишет скрипт, примеры пользователя у девяти операций корня проходят. Оболочка `rptg_host` (команды и
окно) ведёт программу от замысла до DONE — пока на записанных ответах моделей; живого прогона на
моделях ещё не было.

**rptg по собственному методу** — [design/](design/):

* [map.md](design/map.md) — карта архитектора:
  * разрез «ядро методом, оболочка руками»;
  * девять операций ядра;
  * семь подсистем и эскиз сети до листьев — около 116 узлов, 5 уровней;
  * находки самоописания и находки сборки первого кода (§7, §11);
* [types.yaml](design/types.yaml), [rptg.yaml](design/rptg.yaml), [project.yaml](design/project.yaml),

* [SELFCHECK.md](design/SELFCHECK.md) — вердикт прототипа проверок
  [tools/selfcheck.py](tools/selfcheck.py): разбор и вычисление CL, П1, П7, часть П2, связность
  схем, заглушка П4 и П5.

Документы метода:

**Код** — [rptg/](rptg/): листья пишутся по карточкам, обвязку составных узлов генерирует
[tools/codegen0.py](tools/codegen0.py) — затравка будущего `rptg.build`, которая переводит условия
листьями самого `lang`. Статику листьев (Э1) проверяет [tools/leafcheck0.py](tools/leafcheck0.py).

```bash
python -m pytest tests -q
```

Тесты — примеры карточек через обёртки условий, все условия карты, сверка двух исполнений условия и
контрольные случаи языка. Примеры, которым нужен решатель, без `z3-solver` пропускаются с причиной.

**Запуск** (оболочка, [rptg_host/](rptg_host/)):

```bash
python -m rptg_host selftest
python -m rptg_host new app --idea "…" --examples примеры.yaml --preset claude
python -m rptg_host --project app run
python -m rptg_host --project app gui
```

Ключи — только в переменных окружения (`ANTHROPIC_API_KEY`, `OPENAI_API_KEY`, `OPENROUTER_API_KEY`,
`GEMINI_API_KEY` или `RPTG_KEY_<ОПЕРАТОР>`). SDK поставщиков ставятся отдельно: `anthropic` (проверен
1.11), `openai`, `google-genai`, `llama-cpp-python`. Цены Claude в пресетах — открытые данные Anthropic на
04.10.2026; у заготовок в `mixed` — «0», пока не впишут модель и цену. Код моделей проверяется в песочнице
без ограничений ОС.

Следующий шаг — `models test` (смоук шаблона чата у локальных моделей), `models calibrate` и первый
живой прогон.
