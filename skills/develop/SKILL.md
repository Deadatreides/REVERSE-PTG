Разработка идёт через сервер MCP rptg (инструменты kit_*). Порядок:

1. `kit_guide("architect")` — роль архитектора и правила карточек; прочитать один раз.
2. `kit_new(project_dir, package, title)` — новая папка программы.
3. `kit_next` → билет архитектора: spec.md по шаблону Spec Kit (не больше 5 уточняющих вопросов пользователю), корень,
   types.py, дети корня → `kit_submit(files=…)` до «принято». Только карточки, без эталонной реализации.
4. `kit_next` → «approve»: показать пользователю корень и `kit_status`, его ответ — `kit_approve`.
5. Цикл до конца — раннером: `<python kit> -m rptg_kit.run <папка проекта> --detach` (точная команда — в подсказке
   сервера rptg), сразу за ним — сторож, которого печатает `--detach`, фоновой командой. Затем закончить ход.
   Без авторизованного консольного claude — субагенты: `kit_next(limit=4)`, на каждый билет субагент с `subagent_type`
   и `model` из билета, prompt — `dispatch` из билета, вся волна в фоне.
6. «blocked» — причина и отчёт пользователю, его указание — `kit_unblock`.
7. «done» — пакет в папке проекта, проверка — `python -m pytest` там же.

**Экономия токенов — обязательно.**
* Главный чат (вышестоящая модель) получает сигнал только в конце: итог прогона или выход сторожа. До этого — ни
  одного вызова: не опрашивать kit, не читать журналы, run-progress.log, runs/ и код исполнителей.
* Уведомления отдельных субагентов не разбирать и на них не отвечать. Следующий `kit_next` — только после всей волны.
* Работу субагентов не править и проверки за kit не гонять: принимают проверки kit.
* Архитектор работает в свежем чате с малым контекстом и не перечитывает принятые файлы.
